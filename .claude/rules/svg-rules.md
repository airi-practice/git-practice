# SVG 作成ルール

## 1. 使うスキル

SVG を作る・直すときは、導入済みの `svg-art` スキルを使う。

- 模様・グラフ・アイコンのように形が決まっているものは、`svg-art` のスクリプトで作る。パラメータで作れて、あとから値を変えて作り直せるため。
- 挿絵・ロゴ・キャラクターのようにスクリプトで作れないものは、`svg-art` の `references/svg-fundamentals.md` に沿って、SVG を直接書く。
- スクリプトは `python` では動かない。この環境では `py -3` で実行する。

## 2. 挿絵の絵柄

指示がない限り、挿絵と説明図（`docs/images/` の図）は、次の絵柄にそろえる。

- 案内役は、眼鏡なしの二頭身の茶トラ猫にする。頭を大きく、目を大きな黒目にして、かわいさを優先する。
- 赤い首輪と鈴、ピンクのほっぺ、耳の内側のピンク、額の3本のしま、しっぽの先の白を付ける。
- 同じ猫の描き方を、複数の絵やコマで使い回す。コマごとに見た目がずれないようにするため。
- コマごとに動きを付ける。手を振る・考える・跳びはねるのように、場面の気持ちに合うポーズと表情にする。
- 配色は「3. 色の使い方」に従う。

説明図は、猫を登場させたうえで、図の形式の使い分けや代替テキストの書き方など、`.claude/rules/docs-rules.md` の方針にも従う。猫が図の内容より目立たないようにするため、猫は図の端に小さめに置き、図の本体（矢印・文字列・枠）を隠さない。

## 3. 色の使い方

見た目を華やかにしても、色は「何を表すか」で決める。同じものは、どの図でも同じ色にする。読者が色を見ただけで、どの部分の話か分かるようにするため。

| 表すもの | 色 | 面の薄い色 | 文字の濃い色 |
| --- | --- | --- | --- |
| ブラウザ・フロントエンド | 青 `#1565c0` | `#e3f2fd` | `#0d3c75` |
| サーバー・バックエンド | 緑 `#2e7d32` | `#e8f5e9` | `#1b4d1f` |
| データベース | 橙 `#e65100` | `#fff3e0` | `#8a3000` |

役割を持たないものには、次の色を使う。

| 表すもの | 色 | 面の薄い色 | 文字の濃い色 |
| --- | --- | --- | --- |
| 補足・中立（番号を振るだけの並列の枠など） | 灰 `#555555` | `#f1f5f9` | `#334155` |
| 強調・たとえ話 | 黄 `#f9a825` | `#fff8e1` | `#8a5a00` |
| 注意・やってはいけないこと | 赤 `#c62828` | `#ffebee` | `#8e1b1b` |

- 矢印は、送る側の色にする。ブラウザからサーバーへのリクエストは青、サーバーからブラウザへのレスポンスは緑になる。送る側が決まらない往復の矢印は、灰にする。
- 黄色の見出し帯の上の文字は、白ではなく濃い茶（`#5c3d00`）にする。黄の上で白い文字は読みにくいため。
- JSON の項目名のように、役割を持たない複数の項目を色で区別したいときは、紫 `#6a1b9a`・青緑 `#00796b`・赤紫 `#ad1457`・青灰 `#455a64` の4色だけを、この順に使う。役割の色（青・緑・橙）と紛らわしくならないようにするため。必ず項目名のラベルも一緒に付ける。
- 上の色以外は使わない。飾りのためだけに色を増やさない。

図をまたいで迷いやすいものは、次のように決める。

- 元の図で、役割と逆の色（フロントエンドが緑、データベースが紫など）を使っていたら、役割の色に直す。
- `backend/` と `backend_spring/` は、どちらもサーバー側なので、どちらも緑にする。違いはラベルで示す。
- Controller・Service・Repository のように、役割が同じ（サーバー側）で種類が複数あるものは、緑にそろえ、クラス名のラベルと番号で区別する。層ごとに色で対応づける図に限り、Controller=紫（p1）、Service=青緑（p2）、Repository=橙にしてよい。
- 状態を色分けするときは、新しく作る=緑、既存を変更する=黄、変更しない=灰にする。
- ステータスコードは、2 で始まるものを緑、4・5 で始まるものを赤にし、数字の文字でも区別する。
- URL の部品は、`http://`=紫（p1）、ホスト名=青緑（p2）、ポート番号=赤紫（p3）、パス=青灰（p4）にそろえる。
- 並列の項目に p1〜p4 を使うときは、同じ章の図で同じ割り当てにする（例：入力欄=p1、ボタン=p2、表示領域=p3）。
- 見た目の見本そのもの（CSS で変わる色や大きさの例など）は、役割の色や文字の大きさの決まりの対象外にしてよい。見本だと分かるよう、枠で囲む。
- p3（赤紫）は赤（注意）と近いので、同じ図に並べるときは、ラベルで区別する。
- 色の濃い面（見出し帯など）の上は白い文字、白や薄い色の面の上は「文字の濃い色」か `#1e293b` を使う。背景と文字の差をはっきりさせ、読みやすくするため。
- 色だけで区別せず、番号・ラベル・形も一緒に付ける。色が見分けにくい人にも伝わるようにするため。

## 4. 文字の大きさ

文字の大きさは、次の6段階だけを使う。図ごとに大きさがばらばらにならないようにするため。

| 用途 | 大きさ |
| --- | --- |
| 図の主役になる短いコード・数値（`GET`・`200`・`/api/products` など） | 28（等幅の太字） |
| 図の見出し | 22 |
| 枠・カードの小見出し | 18 |
| 本文 | 15 |
| 注記・補足 | 13 |
| 猫の台詞 | 16 |

- 13 より小さい文字は使わない。
- 28 は、短くて目立たせたいコードや数値だけに使う。枠に収まらない長い文字列は 22 にする。
- コードは等幅で書く。コード枠の中は 13 の等幅でよい。13 でも1行に収まらないコードは、内容を変えずに行を分ける。長いコードが多い図は、横に並べず、縦に積む。
- ディレクトリ名は 18 の等幅の太字、ファイル名は 15 の等幅の太字にする。
- 同じ役割の文字は、同じ大きさ・同じ太さにする（例：すべてのカードの小見出しは 18 の太字）。
- 強調は、大きさを変えずに太字か色で行う。

## 5. リッチな見た目にするときの範囲

グラデーション・影・角丸・アイコンで華やかにしてよい。ただし、わかりやすさを最優先にして、次の範囲に収める。

- グラデーションは、同じ色の濃淡（上が明るく下が少し濃い程度）にする。色相が変わるものは使わない。
- 影は、すべての図で同じ強さ（ずらし 4、ぼかし 5、不透明度 0.16 程度）にそろえる。
- アイコンや絵は、図の意味を助けるものだけを置く（例：天気のページなら太陽）。飾りだけの絵は置かない。
- 図の読む順番がある場合は、番号バッジ（1・2・3）を付けて、順番を示す。
- 絵や飾りを足して、図の中の文字が小さくなったり、読みにくくなったりしたら、飾りのほうを減らす。
- アイコンは、`svg-art` の `generate_icon.py`（`py -3 generate_icon.py --list` で一覧）で作れるものを優先する。データベース・サーバー・モニターは一覧にないので、必要なときは図の中に自分で描く。
- 図は、共通部品（`tools/svg/rich-lib.js`。カード・ラベル・矢印・往復の矢印・番号バッジ・アイコン・猫の吹き出し）で組み立てる。色・文字の大きさ・影が、図ごとにずれないようにするため。
- 各図の作り方は `tools/svg/builds/build-<図の名前>.js` にある。図を直すときは、SVG を直接書き換えず、この build ファイルを直して `node tools/svg/builds/build-<図の名前>.js` で書き出す。台詞や色を、あとから一括で変えられるようにするため。新しい図も、同じ形の build ファイルを足して作る。
- 猫の描き方は `tools/svg/cat.js` にある。猫の見た目は、ここ以外で変えない。

## 6. 吹き出しの台詞

- 猫の台詞は、講師が初学者に教える口調にする（「〜だよ」「〜なんだ」など）。
- 台詞は1つの吹き出しに3行程度で収め、1つの吹き出しで複数の概念を説明しない。
- 課題の答えを台詞で言わない。考え方やヒントにとどめる。教材として、学習者が自分で考える余地を残すため。
- 台詞でも、専門用語だけを並べず、何をしているのかが分かる日本語を添える。

## 7. 書き方

- `<title>` と `<desc>` を必ず付けて、図が伝える内容を文で書く。見えない人にも内容が伝わるようにするため。
- フォントは `'Segoe UI','Yu Gothic UI','Meiryo',sans-serif` を指定する。`<img>` で表示する SVG は外部フォントを読み込めないため。
- 日本語の文字は `<text>` の1行ごとに分けて配置し、吹き出しからはみ出さないようにする。
- `<text>` は行頭の空白を詰めるので、字下げを見せるときは `&#160;` に書き換える。共通部品の `t()` は `&` を書き換えてしまうため、`t()` を使うときは、改行しない空白（U+00A0）の文字そのものを書く。
- グラデーション・影・矢印は `<defs>` にまとめて、使い回す。

## 8. 確認の手順

SVG は書いただけで終わらせず、必ず見た目を確認する。

1. ヘッドレスの Chrome で PNG に変換する。`--window-size` は SVG の `viewBox` の幅と高さに合わせる。
2. 作った PNG を画像として読み込み、文字のはみ出し・重なり・崩れがないかを見る。
3. 崩れがあれば直して、もう一度 PNG にして見る。

確認が済むまで、完成として報告しない。
